# 完成记录

## 结论与资源审计

用户引用的是 V6 制作流程：4096×1783 的字框在 tools/compile-slogans-v6.mjs 构建时生成，手机不在每次切换时执行字体绘制。V6 运行时确实会解码、上传并缓存整幅遮罩，其中字框有效区域约 3.696%。RGBA8 含 mipmap 的理论 GPU 占用每句约 37.15 MiB；六句都使用过并保留时约 222.88 MiB。这是格式/尺寸估算，不是 Safari 实测内存或特定卡顿归因。

前一轮 V7 已裁成 289×934 并使用 R8，六句合计约 2.06 MiB，保持原字形像素和 UV 定位；V7.0.3 又在进入前预热六句。该成果属于此前工作，本轮没有重复生成或缩小文字。

其他开销：

- 城市法线解压数据：V7 轻量约 3.48 MiB、标准约 13.94 MiB、细节约 55.72 MiB。旧的 chunks 收集再拼接会短时间保留两份完整原始数据，是本轮可消除的重复分配。
- 固定花纸法线存在同样的流读取路径，因此共享此修复。现有逐分区缩放、图集护边和半精度数据不变。
- 默认背景 1248×2596，RGBA 解码尺寸约 12.36 MiB；色盘有 512 像素上限且已复用色域，不属于每次操作重新绘制 4K 的情况。本轮保持背景和色盘画面。
- V6.0.3 新玻璃合成器是独立 WebGL 画布，每次 render 会上传杯子画布，并保留多份离屏目标与光学贴图；其缓存主要按份数而非字节控制，后续同步 V7 前应独立纳入预算和帧耗验证。当前 V6 另有未提交下载修正，未修改、提交或发布 V6。
- 首次预载的网络量仍是 10.42 MiB，上一轮公网约 106–123 秒的边界没有因本轮 CPU/GPU 优化而自动解决。

## 本轮实际修改

1. readExact 按清单声明的精确大小预分配一个数组，收到流块即写入，不保留完整 chunks 列表和最终拼接副本；下载与 Worker 解压共用。短读、超限、上游错误/取消均拒绝并释放 reader，保留字节进度、SHA256 和 HFN 数值校验。流内部缓冲、当前块、压缩数据和 GPU 仍另计，不能把目的数组大小称为进程总内存。
2. 城市/文字所有材质组都位于局部反射捕获时隐藏的 cup-wall-and-recessed-foot 网格上。切换这些材质只使主画面失效，不再无效重建局部反射。几何/拆解变化、可见花纸变化、杯盖视角反射保留。
3. 固定花纸提清完成后，setFixedRelief 已刷新反射；删除其后的第二次重复刷新。
4. 产品版本提升为 V7.0.4；资源仍为 v7-1，195 份资产字节未改。
