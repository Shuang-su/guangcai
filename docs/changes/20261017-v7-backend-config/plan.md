# V7 后台配置数据表与开发交接补全

## 1. 已确认的数据含义与交付边界

按你确认的“暂时没有后台模板，先按当前项目整理”，以 **V7.1.1、资源版本 `v7-2`** 为依据，交付可以查阅、复制和做字段映射的 Excel，以及同源 JSON 数据。公司后台的实际导入格式，待其模板明确后再映射。

当前实现需要向同事明确三点：

- **城市拓展数据适合用 JSON 对象表达。** 内容包括城市 ID、名称、资源版本，以及缩略图和各清晰度的遮罩、法线资源描述；图片文件存 COS/CDN，数据库保存版本与引用。若后台拓展字段只能存字符串，则保存序列化 JSON，使用时解析一次。
- **当前没有名为“色域数组”的公共字段。** 预设包含深色、浅色两个 sRGB HEX 值；作品保存 `hue / saturation / lightness`。表格分别提供 `[darkHex, lightHex]` 和 `[H, S, L]`，注明顺序与用途，避免混用。H 范围为 0～360，S、L 为 0～100；当前界面的明度滑块范围另为 20～65，必须与数据契约范围分开说明。
- **材质保存连续参数与配方版本。** 保存 `material`、`materialX`、`relief`，由前端配方计算金属度、粗糙度、清漆层和法线强度。表格提供计算规则与参考结果；作品不需要重复保存这些派生值，也不需要为每个颜色生成一套 PBR 图片。

本轮交付数据、导出工具和文档，沿用现有 `DesignConfig`、`ResourceManifest` 与 HTTP 接口。

## 2. Excel 与配套数据

交付一个 `.xlsx`，按以下六张工作表组织。数据直接提取自当前源码与资源清单，保留来源提交、资源版本和字段说明。

| 工作表 | 内容与填写方式 |
|---|---|
| **录入说明与字段** | 字段路径、类型、必填性、默认值、范围、用途、存储位置；明确哪些是后台配置、作品参数、前端派生值和运行状态。附深圳默认作品的完整 JSON。 |
| **城市配置：23 城** | 实际菜单顺序、城市 ID、中文名、资源版本、manifest 引用、缩略图及三级遮罩/法线资源 ID；提供每城完整的拓展 JSON。 |
| **颜色配置：5 套** | 同心金、共融绿、繁盛红、焕新紫、开放蓝的真实预设 ID、菜单顺序、深浅 HEX、RGB、默认 HSL、默认材质参数及完整 appearance JSON。加入可见色块。 |
| **材质参数** | `material`、`materialX`、`relief` 的类型、范围、默认值、配方含义；附二维材质九个代表位置的计算结果，并标为连续材质的参考采样。固定金线参数单独列出。 |
| **祝福语：6 组** | ID、文字、裁切遮罩资源、尺寸、`uvRect` 数值及坐标含义，交代字形与边框的来源及预热机制。 |
| **资源明细** | 当前 manifest 的 195 项资源：用途、档位、编码、通道、色彩空间、尺寸、字节数、哈希和路径；原始清单内存值与运行时 RG16F 估算分列。 |

配套 JSON 使用与 Excel 相同的数据源，保存完整数值精度；Excel 中的数组和对象以可复制的合法 JSON 文本呈现。资源保留原始相对路径，同时列出解析后的发布根相对路径及当前预览地址，方便替换 COS 域名。

所有文件集中放入仓库的交接目录，并提供可重复执行的导出命令。**Excel 是配置参考，现有前端不会直接读取它；JSON 导出也不自动改变运行时接口。**

## 3. Issue 与交接文档补充方式

更新现有 [Issue #29](https://github.com/Shuang-su/guangcai/issues/29)，在顶部增加“后台同事从这里开始”：表格下载、字段说明、完整 JSON、接口示例及配置步骤。README 同步入口。

现有 12 项性能说明保留，并逐项补齐 **触发条件、处理流程、数据格式、关键阈值、失败处理、源码入口、验证证据和接入方责任**：

1. **进入前加载门槛**：下载完成、解码完成、高清应用和首帧就绪分别代表什么。
2. **城市预加载与切换**：全部低清、当前及左右邻城高清、动态取消、最新选择生效。
3. **三级资源与花纸图集**：尺寸、分区护边、UV，以及禁止直接缩整张图的原因。
4. **高精度法线**：HFN1 容器、Worker 解压校验、RGBA16F 到 RG16F 的运行时处理。
5. **祝福语优化**：构建时裁切、R8 遮罩、UV 还原、六组预热与切换流程。
6. **调度与容错**：请求和解码并发、120 秒无进度超时、重试范围、取消与后台暂停。
7. **缓存与内存预算**：压缩文件和 GPU 两层缓存、常态与切换峰值、释放时机及估算边界。
8. **反射与按需绘制**：反射失效条件、临时缓冲、静止停绘、后台暂停和截图捕获。
9. **液态玻璃降级**：DPR 调整、持续帧耗与真实预算判断、切城期间的豁免、磨砂回退。
10. **上下文恢复**：保留作品、取消任务、轻量重建、重新提清和失败重试。
11. **资源版本与西安修正**：`v7-2` 复用 `v7-1` 的关系、旧作品回放和不可覆盖的哈希资源。
12. **COS 与正式后端接入**：CORS、MIME、缓存、`.hfn.gz` 响应规则、身份归属、保存与分享。

新增“后台配置能改变什么”说明：当前配色、城市和版本仍存在前端白名单。配置现有 23 城与 5 套颜色可以直接对应；**增加新城市、配色、祝福语或资源版本，需要同步资源生成、清单、校验契约和前端目录**。列清每类扩展涉及的步骤，避免同事误以为后台新增一行就会自动出现。

## 4. 验证与交付完成条件

- 核对 23 城、5 套颜色、6 组祝福语及 195 项资源的完整性、唯一 ID、菜单顺序与来源；所有 JSON 可解析，作品示例通过现有契约校验。
- 对五套颜色的 HSL/RGB 转换、材质代表位置和边界值进行独立核对；确认表格没有把 UI 范围当成接口范围，或把派生参数当成必填字段。
- 校验所有资源路径能定位到真实文件；特别覆盖 `v7-2` 对 `../v7-1/` 的引用。JSON、Excel 和文档示例必须一致。
- 检查每张工作表的显示效果、长 URL、JSON 文本、数值精度与筛选功能；从表格取一套城市/颜色/材质配置完成保存与还原验证。
- 在独立交接分支形成提交，按此前授权推送并合并；更新 Issue 后回读其正文与文件链接。提交记录明确本轮新增内容，历史性能结果标注原测试版本，真机和正式 COS 未完成项继续保留。
