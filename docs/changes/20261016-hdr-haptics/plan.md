# 最终实施计划

1. 为现有 XYPad 的彩色底图与白色选点增加可选 HDR 输出层，继续使用当前 Canvas 底图、DOM 选点、点阵和事件。材质 XYPad 复用相同能力，竖条仍使用饱和度激活反馈。杯身 Three.js 输出不改。
2. 仅在安全上下文、真实显示动态范围查询及 WebGPU 能力均满足时请求 GPU。采用 `rgba16float` 和 `toneMapping.mode=extended`，回读实际配置；不支持、配置被忽略或设备丢失时使用原 SDR 控件。
3. 彩色底图在线性光空间进行曝光增益，再转换回 sRGB 编码。激活增益为 1 至 2.25 倍线性曝光，不再直接放大 gamma 编码 RGB；维持底层 HSL 和滑条 20–65 范围。原约 1.58/2.13 的读回值不是颜色正确性或亮度目标。
4. HDR 底图仅在原底图重绘时上传；拖动只改变 uniform。多控件共享 GPU 设备，停止、销毁、设备丢失及显示能力改变时释放或回退。
5. 增加受信任触摸触感：激活 8ms，移动约 0.45–0.8 个点距离散触发 4ms，进入默认点/边界 8ms，松手 6ms，重置 12ms。全控件共用至少 55ms 间隔；按相对最后触发位置的位移判断，过滤轻微往返抖动。鼠标、键盘、程序事件、减少动态效果及不可见页面不请求震动。
6. 使用标准 Vibration API；记录 iPhone Safari 不提供通用网页马达调用的边界，不用隐藏控件绕过。真机手感单独验收。
7. 跑现有应用测试、TypeScript、直接 Vite 构建及现有 Playwright 回归。增加 HDR 配置、真实浮点像素回读、线性颜色响应、资源复用、丢设备回退、触感请求及防抖专项。用内置浏览器无能力覆盖检查实际配置。
8. 保存用户截图来源、专项结果、桌面/手机视口截图及完成记录，形成本地提交。截图只作为 SDR 外观记录；不将浮点回读或震动请求等同于屏幕亮度/真机马达验收。
