# 历史恢复计划

1. 固定当前已上传的 1.0、2.0、2.1 及归档证据。使用独立恢复分支，不改写既有提交。
2. 仅提取原始会话中实际文件操作与已保留的 before 文件、素材及部署清单，按真实时间重建可证明的源码节点。原始会话不入库；不记录隐藏推理、系统信息或凭据。
3. 补建提交使用当前真实日期，每个节点记录原修改时间、来源、恢复范围和验证结果；未证实的部分明确列为缺口。历史预发布节点使用 1.0-pre.N / 2.0-pre.N 标识，避免与已分配的 1.0 / 2.0 / 2.1 混淆；这些编号不代表新增线上发布。
4. 核验源码端点、构建、合理的既有测试和可用历史部署字节。保留必要素材，避免依赖历史临时目录。
5. 提交、推送，并在同一仓库建立历史恢复 issue / PR 与索引；回读远端。仅操作归档，不部署或改动生产配置。
