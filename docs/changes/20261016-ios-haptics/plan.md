# iOS 触感兼容实施计划

基线 `32c586f`，分支 `codex/ios-haptics`，关联既有交互 Issue #25。

1. 读取完整分享对话，核对 WebKit 官方触感引入和可信事件修复；审查对话引用的 ios-vibrator-pro-max 3.0.4 原生 switch 拖动机制。
2. 原生 Vibration API 可用时保留现有路径。iOS 18 起、标签仍转发可信事件的旧 WebKit 在按钮点击时采用隐藏标签的同步请求；iOS 26.5+ 或已修复标签信任的 WebKit 使用真实触摸下的局部 switch 覆盖和运动机制。17.x 及不具备能力的平台安静降级。
旧版持续拖动也使用原生 switch 手势，以避免旧标签点击授权约一秒后过期。
3. 新版路径仅附着在色盘、材质盘、明度滑杆及已有触感的切换／恢复按钮。保留原视觉、数值与辅助键盘控件，不改写 document.body、navigator.vibrate 或原控件的指针捕获方法。
4. 沿用真实触摸、可见页面、减少动态效果和 55 ms 节流；请求为 4–16 ms，不运行后台弹窗、长震动或阻塞主线程的循环。全程可取消，控件销毁时移除局部辅助层。
5. 验证三种能力路径的事件路由、按钮单次触发、拖动、取消、减少动态效果、缓存与完整应用回归。自动化只能验证请求与状态，不能证明真实 iPhone 马达效果；在记录中明确真机验收边界。
6. 完成后保存来源、修改、测试和 checkpoint，并延续已授权的 V5 在线预览更新；保留全填色城市与关闭 Netlify 标识的设置。
