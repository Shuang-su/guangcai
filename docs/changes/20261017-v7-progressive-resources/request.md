# V7：低内存渐进加载与上线接入准备

## 1. 目标与已确认边界

V7 分为两条主线：**让 iPhone 13 mini／iOS 18 能稳定运行，///也不是，其实整理好我们现在的资源结构并最好是提供模拟接口来实现类似的功能以供参考方便部署就行了**

已确认的分工与体验要求：

- 我们完成性能优化、资源整理、数据与接口规范、模拟服务和独立联调样例。
- 采用低清先显示、近看再提清、主画面分辨率动态调整的策略。**保留杯壁与杯盖反射，以及金线、字形、配色和材质表现。**

本轮只读检查发现，当前并非一次下载包含所有城市的 ZIP，主要负担来自高分辨率贴图与 `.hfn.gz` 高精度法线解压后的占用：

| 当前资源 | 本轮读取结果 |
|---|---|
| 固定花纸＋默认城市＋文字等首屏贴图 | 文件合计约 **51.2 MiB**，不含 JS、背景和界面资源 |
| 杯碟法线 | 8192×1152；压缩文件约 **23.2 MiB**，原始 RGBA16F 数据约 **72 MiB** |
| 单座城市法线 | 4096×1783；原始数据约 **55.7 MiB** |
| 首屏上述贴图的 GPU 存储 | 按格式和 mipmap 估算约 **507 MiB**，尚未计入反射、阴影等缓冲 |

这些是资源统计与理论估算，尚未通过真机定位崩溃原因。图片压缩主要减少下载量，像素尺寸和 GPU 格式决定运行占用，这也符合 [Three.js 的纹理内存说明](https://threejs.org/manual/pages/textures.html)。

## 2. 性能实现方案

**资源按用途和清晰度分级。**

- 从现有母版生成轻量、标准、细节三个档位。城市展开图宽度分别为 1024、2048、4096；固定花纸按相近的最大边长生成，保持分区与比例。
- 手机首屏使用轻量档，近看提升到标准档；桌面在预算允许时使用细节档。消费者页面不直接加载原始 8K 花纸。
- 固定花纸逐分区缩放并重新生成图集护边，同步更新图集参数，避免简单缩图造成串色、接缝和法线方向错误。
- 祝福语保留既有字形与排版，只保存实际字框区域，通过 UV 定位还原位置；使用单通道遮罩，避免六句话分别缓存整张 4K 展开图。
- 固定花纸的粗糙度与金属度合并为共享通道贴图；城市继续通过结构遮罩与参数着色，调色和调整材质不生成新图片。
- 颜色与遮罩采用 WebP；法线首版保留高精度表达，优先通过尺寸分级降低占用，避免金属高光出现量化断层。所有生成物保留来源哈希，原稿保持完整。

**加载采用可取消、受内存预算约束的调度。**

- 首屏只加载当前作品的轻量资源、必要界面和可见缩略图。城市列表按可见项和相邻项加载，不预解码所有城市。
- 用户进入近看视角或放大到轻量资源不足以覆盖显示像素，且停止操作约 300ms 后，加载当前可见部件的更清晰资源。
- 全部图片与法线共用请求队列；手机同时最多两项资源请求、一个解码任务。法线解压和校验放入 Worker。
- 快速切换时取消过期请求与排队任务；无法中断的解码完成后立即释放结果。新资源完整通过校验后再替换，加载失败继续显示已有版本。
- 缓存从“两个城市、六套文字”改为按字节预算管理。计入当前资源、候选资源和切换期间的重叠占用，淘汰后同时释放 GPU 纹理与 CPU 引用。资源释放遵循 [Three.js 的生命周期要求](https://threejs.org/manual/pages/how-to-dispose-of-objects.html)。

**保留反射，减少重复工作。**

- 保留现有环境照明、杯壁局部反射和杯盖平面反射；优化其失效条件，只在相关相机、器件或材质变化时更新。
- 模型静止、自动旋转关闭且动画结束时停止重复绘制；页面进入后台时暂停渲染与非必要加载。
- 手机主画面 DPR 从 1.5 开始，根据持续帧耗时在 1～2 之间调整，界面文字保持正常清晰度。
- 关闭消费者页面不必要的 `preserveDrawingBuffer`；需要导出画面时显式绘制并捕获。
- 处理 WebGL 上下文丢失：保留作品参数，恢复时从轻量资源重建，避免一次性重新加载最高档资源。

初始工程预算：手机首屏贴图估算占用不超过 **64 MiB**，常态纹理与渲染目标合计不超过 **128 MiB**，切换峰值不超过 **192 MiB**。这些是应用资源管理预算，不代表 Safari 的系统内存上限；预算不足时延后或拒绝高清升级。

## 3. 资源组织与作品数据

采用以下关系：

**公司账号 → 用户作品 → 作品版本 → 指定资源版本与材质配方 → 分享快照**

资源由对象存储/CDN 分发，数据库保存归属、版本和索引。

| 数据类别 | 存放内容与职责 |
|---|---|
| 公司用户 | 沿用公司稳定的用户 ID；需要映射时使用身份系统标识与主体 ID，不以昵称、手机号或设备标识作为作品主键 |
| 资源发布版本 | 模型版本、固定花纸、23 城描线、6 组祝福语、配色与材质配方、照明配置及资源清单地址 |
| 用户作品 | 作品 ID、所属用户、标题、当前修订号、创建与更新时间 |
| 作品修订 | 资源版本、模型版本、城市、祝福语、颜色参数、材质二维参数、浮雕参数及材质配方版本 |
| 分享记录 | 指向确定的作品修订，记录分享令牌与撤销状态；公开响应不包含作者账号信息 |

关键约定：

- **保存作品保存参数与资源引用。** 所有作品复用城市与固定花纸，避免为每件作品复制整套贴图。
- 现有杯子是前端程序生成的几何模型；反射也包含运行时计算。因此清单除了 PBR 贴图，还需要模型和照明／材质配方版本，不能只约定图片 URL。
- PNG、SVG、高精度母版、字体和来源记录保留在制作资料中；消费者发布包只包含实际运行需要的资源，开发与审计入口单独构建。

新增两类核心契约：

- `ResourceManifest`：资源 ID、版本、通道用途、色彩空间、编码、尺寸、各清晰度 URL、文件大小、解码大小、哈希，以及必要的 UV／图集参数。
- `DesignConfig`：数据格式版本、资源发布版本、模型与材质配方版本，以及完整作品参数。清晰度、缓存和设备性能档位不写入作品内容。

## 4. 前后端接口与交接边界

以下路径作为交接规范的默认命名，公司可在网关映射到现有服务；前端通过配置设置 API 与资源根地址，支持部署在独立域名或子路径。

| 接口 |
| `GET /api/v1/bootstrap` | 返回当前资源发布版本、目录地址、默认作品与支持的数据格式版本 |

| `GET {CDN}/…/manifest.json` 及具体资源 URL | 按当前作品与清晰度加载贴图、描线遮罩和配置 |
|  |

前后端必须共同遵守：

- 资源使用带版本或内容哈希的 URL 长期缓存；版本入口可更新。CDN 配置正确的 CORS、MIME 和压缩响应头，避免法线重复解压或跨域纹理失败。

交接包包含 OpenAPI、作品与资源 JSON Schema、逻辑数据关系、示例数据、模拟服务、身份适配说明，以及 CDN 与部署配置清单。数据库产品、后端框架和身份协议由映射落实。

## 5. 验证、交付与实施顺序

按三个阶段形成可审查的成果：

1. **基线与资源优化**：固定 V6 基线，记录下载、解码、贴图与渲染目标占用；先完成深圳、北京及固定花纸的分级对照，再扩展到全部城市与祝福语。
2. **运行时优化**：接入资源调度、按预算缓存、渐进提清、动态分辨率和恢复机制，完成旧功能回归。
3. **接入合同与联调样例**：交付接口文档、数据结构、模拟服务及作品保存／还原／分享演示。

验收覆盖：

- **真机稳定性**：iPhone 13 mini／iOS 18 Safari 连续使用 30 分钟，覆盖冷启动、遍历 23 城、切换 6 组祝福语、快速连续切换、近看、旋转、拆解及前后台往返；无页面重载、白屏或不可恢复的上下文丢失。
- **性能目标**：10 Mbps、100ms RTT、冷缓存条件下，首个完整可交互画面所需总传输量目标不超过 5 MiB，出现时间目标不超过 6 秒；目标设备交互以稳定 30fps 为最低验收线。目标未达到时保留未通过状态。
- **画面回归**：固定相机对比金线、字形、花纸接缝、白瓷、金属高光及两类反射；近看提清不改变作品配色或材质参数。
- **资源生命周期**：多轮城市与文字切换后，缓存和资源计数回到预算范围；测试取消、超时、缺失资源、乱序返回及上下文恢复。
- **数据与接口**：导出后重载能够还原；测试账号隔离、登录过期、并发保存、重复提交、匿名分享、撤销分享与旧资源版本回放。
- **既有体验**：保留颜色／材质操作、菜单、自动旋转及触感路径；浏览器自动化与实体 iPhone 验收分别记录。

V7 从最终确认的 V6.0.1 提交建立独立分支，保护当前尚未提交的兼容修正。每阶段形成验证记录与本地 checkpoint；资源编译前核算磁盘空间，缓存放在项目 `.codex-work/`。本计划交付前端优化与上线接入准备，正式后端联调和生产发布由后续上线阶段完成。
