## 当前实现

- 内置 ImageGen 完成两城详细原稿与局部修订。最终采用白底源图：北京 1899×828，深圳1900×828；原图、提示词、透明研究稿和失败的北京底线擦除稿全部保留。
- 北京右端由三座可见城楼改为两座，最后一段连续下行，去除横直地平线和下伸尖楔。祈年殿以PSD为细节参考，但本轮生成稿不是原PSD逐像素复制。
- 深圳保留原有楼群比例、折面、细密窗格与市民中心屋檐/栏杆/台阶，只去右桥。此前程序化建筑保留为历史实验，并阻止其构建脚本覆盖当前生成母版。
- 编译器以生图原稿决定建筑形态，局部拟合真实像素轮廓为可编辑SVG；不以几何图元重画地标。白底通过独立的结构线、填色封闭和孔洞种子提取，不把整张白底当覆盖。
- 北京底部辅助封闭只进入填面，不进入金线或法线。原始源图不被脚本修改。基于1px容差的原笔画召回，北京约99.59%、深圳约98.25%；这是像素提取质量指标，不等于审美或建筑准确性认证。
- 延续5433×2365母版与4096×1783运行通道、五色/HSL、固定金线、连续材质、独立浮雕；原尺寸、固定花纸与模型不变。

## 可复用流水线

- `npm run pipeline:v5`：已审核源稿哈希 → 编译 → 素材检查 → 应用测试 → 生产构建 → 临时本地服务 → 浏览器检查 → 构建/源码摘要。任一阶段失败即停止。新的生图须更新真实审查记录；不自动宣称用户批准。
- `npm run deploy:v5`：要求已提交、工作树干净、准备结果通过、源码/构建哈希一致；只允许独立V5站点。使用Netlify文件摘要API原子发布，回读文件哈希/部署ID/公开release.json，检查真实404、旧站点未变，再执行在线浏览器测试并保存完整快照。
- 已创建独立站 `guangcai-no1-china-v5`，ID `b1fce272-cf28-41e5-8366-024c314b615f`。不重绑现有 `.netlify/state.json`，不配置Git自动部署。V4/V3/原版站点ID被显式保护。
- 发布凭据仅在进程内读取已有Netlify登录或环境变量；不写源码、缓存、记录。独立预览设置noindex，当前同名V5资源使用revalidate。
