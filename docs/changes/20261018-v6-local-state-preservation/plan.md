# 保存与清理方案

1. 检查旧V6唯一未提交文件，与其HEAD、GitHub原始blob比较字节并尝试解析XML。
2. 原样保存未提交文件到本目录，以`.svg.bin`标记其为异常历史字节证据，不接入消费者页面。记录原路径、来源HEAD、前后哈希、四个差异字节及解析错误；保留不可变部署原文件。
3. 提交并推送恢复证据，GitHub回读逐字节确认，再对旧工作区执行精确单文件还原。记录发布归档未变，现有V6/V7站点不部署。
4. 旧V6作为共享Git主仓库仍支撑旧V7及archive-index工作树。保留`.git`、被忽略恢复资料和两个关联工作树；将旧V6检出detach到原HEAD、删除已合并V6分支，收窄其sparse checkout为根目录说明文件，清除已保存的重复源码和资源展开副本。核对清理前后状态和磁盘空间。
5. 提交结果回执，合并文档PR，最终当前交付仓库回到与远端一致的main并清理本轮临时分支，更新Issue #35。
