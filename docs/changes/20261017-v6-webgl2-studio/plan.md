V6 继续使用现有杯子模型、城市材质和创作控制，新增面向用户的页面，并将完整开发功能与对比验收独立出来。

| 地址 | 用途与内容 |
|---|---|
| https://guangcai-no1-china-v6.netlify.app/ | C 端预览：23 城、6 组祝福语、五种配色预设，以及现有自由调色、材质和明度控制 |
| /dev/ | 完整工作台：保留现有信息、旧图样、调试功能、视角、背景及材质校准，增加 V6 状态与诊断 |
| /audit/ | 对比审计：原版与 WebGL2 玻璃效果、城市填色、文字边框、性能及回归结果 |

- 布局依据提供的四张 UI 参考：大面积杯子展示、右侧视角工具、底部创作面板；底部面板采用通透的液态玻璃。
- 保留“选择城市／选择颜色／选祝福语”的切换关系，不加入参考图中的底部导航、作品发布、个人作品库、账号或排行榜。

- 现有 V5 线上站点作为历史预览保留；后续开发和审计转到 V6。

## 2. 液态玻璃：忠实迁移 Glass-HQ 的材质图生成后端

以 Glass-HQ/liquid-glass 的具体实现为基础，为原库增加 WebGL2 后端。固定上游提交 9f5bfc7daa7be5d20a41b94d841b8f065de655fc，在项目内保存必要源码、MIT 许可、来源和迁移补丁记录，便于对比与后续同步。

原库通过 GPU 生成材质图，再由 SVG 滤镜作用于实时内容；它也提供独立 DOM 接口，可以接入当前 TypeScript 工程。

直接保留：Clear／Regular 材质算法、轮廓几何、圆角、折射、边缘高光与明暗处理；原有弹簧、按压、拖动、选中指示器及形状过渡控制器；SVG 合成、材质图编码、胶囊切片、缓存、预热和资源释放方式。使用原库 DOM API 接入，继续使用现有页面框架与创作控件。

需要迁移：
- 将原 maps.wgsl 按公式与通道逐项翻译为 GLSL ES 3.00，保持“折射位移图＋边缘覆盖图”两张图的含义、尺寸、边距和透明度一致。
- 新后端继续满足 MaterialRenderer 的 warmed、render(geometry)、dispose() 契约，返回同样的像素格式；沿用原有批次调度和图集布局。
- 轮廓线段采用只读数据纹理传入，避免依赖过大的 uniform 缓冲；输出使用 RGBA8。统一处理坐标原点、像素读取方向和非预乘透明度，不给材质图添加色彩转换。
- 使用独立的小型 WebGL2 上下文生成材质图，按批次通过 PBO 与 fence 完成读取，避免干扰杯子的 Three.js 渲染状态。
- 后端在初始化时确定；缓存标识包含后端与着色器版本。初始化失败、上下文丢失和销毁时，正确结束待处理请求并释放资源。

C 端默认使用 WebGL2。原始 WebGPU 后端保留在审计页，放入独立对照实例，避免共享缓存掩盖差异。另一个项目只用于参考验证方法和已知问题。

杯子 canvas 与现有背景共同纳入原库明确的内容层，并按上游要求提供不透明的背景底层；菜单文字与操作控件保持清晰。先验证旋转中的杯子、背景和玻璃折射是否同步，再完成整套界面。

WebGL2 迁移不会自动消除 Safari 的 SVG 合成成本。保留已确定的透明玻璃兼容效果，在能力不足或初始化失败时启用；实际使用的后端、降级原因只出现在开发与审计页。兼容效果与完整迁移效果分别记录验收结果。

## 3. 23 城、六组祝福语和 SVG 边框

以本次“23个城市线稿”目录为 V6 正式图样来源。C 端只出现这 23 个城市，每城一个选项；旧图样及历史变体继续保留在开发和资料体系中。

- 新稿按其原始构图接入，包括其中已有的桥、山线与底线，不再套用早期去桥规则。
- 使用现有 5433 × 2365 母版坐标、4096 × 1783 运行输出；按比例归位，避免拉伸和重复缩放。
- 这批 PNG 是白底不透明图片，使用线色与背景识别提取结构，不能把 alpha 当作线条。
- 延续全填色规则：建筑及图样内部区域填色，外部天空保持白瓷，不增加镂空制作。
- 固定金线与主体填色分开，换颜色、材质时金线保持金色和金属反射。

六组祝福语固定为：开放包容、创新驱动、合作共赢、共建共享、携手同心、拥抱瀚海。

使用新提供的阿里妈妈东方大楷字体包。已核实 WOFF 中六组文字所需的 22 个不同汉字全部齐全，字体为阿里妈妈东方大楷 Regular，版本 1.006;beta。

- 原样保存 WOFF、WOFF2 和来源记录；字体加载优先 WOFF2、备用 WOFF，并验证两种格式实际渲染一致。
- 杯身文字使用东方大楷，界面其他文字使用清晰的界面字体。
- 将“边框.png”按原轮廓重绘为可编辑 SVG，保留双线、卷曲装饰、上下比例；保留原 PNG 作为对照。
- 文字四字竖排，置于边框内部，文字与边框统一固定为金色。
- 构建时等待字体加载完成，生成六套文字与边框遮罩；字体缺失或替代字体参与渲染时检查失败。
- 六套文字适用于全部 23 城，共享独立文字贴图，避免制作或预载 138 套完整城市贴图。

## 4. 共享工程与交互兼容

三个入口共用模型、城市编译结果、材质系统和选择控制器，通过页面配置决定目录、默认值和界面能力。

- 增加页面配置，明确消费者、开发和审计模式；C 端从入口就只构建所需界面。
- 扩展选择状态以支持六个独立祝福语标识，保留现有 applyCityArtwork(pack) 兼容入口。
- 为文字材质增加可选的固定金色配置：V6 启用，旧图样保持原有行为。
- 拆分城市结构缓存与文字缓存。切换祝福语只更换文字；调色和材质继续更新参数；切城保留当前创作参数。
- 保留整组加载成功后切换、失败保留当前效果、快速连续操作只应用最后一次选择的机制。
- 玻璃表面和原库交互控制器围绕现有控件接入；保留已经工作的脉冲、触摸节点、坐标换算及短屏放大动效，避免新增容器抢占拖动事件。
- 根目录、/dev/、/audit/ 使用同一份静态资源，处理直接访问、刷新、尾斜杠和资源路径；C 端不放开发入口。

## 5. 实施顺序、验收与发布

按三个阶段形成可审查的提交：
1. 玻璃迁移与对照页。先实现原版 WebGPU／WebGL2 材质图对比，验证真实杯子和背景的合成。覆盖圆形、胶囊、圆角矩形、自定义轮廓、不同尺寸、明暗模式及 DPR；检查通道方向、边缘、高光、缓存、批次和上下文恢复。
2. 素材与消费者页面。编译 23 城、六套文字和 SVG 边框，接入消费者布局、共享状态及完整开发入口。
3. 回归与独立 V6 发布。完成自动检查、浏览器视觉检查和设备验收，生成发布记录后发布 V6。

验收至少包括：
- 迁移一致性：相同输入生成相同尺寸与通道的两张图；像素差异可视化，并对明显超出量化误差、边缘错位或高光变化逐项定位；对比相同操作下的形状与弹簧动效。
- 实时通透性：转动杯子、切换背景、拖动选项时，玻璃内外画面同步，无黑底、重影、停留旧帧或文字模糊。
- 素材与金色稳定性：检查 23 城构图与填色、六组文字字形与边框；遍历颜色和材质后，线条、文字及边框保持固定金色。
- 交互与性能：覆盖短屏、横竖屏、连续快速换城换字、拖动、取消手势、加载失败与重复挂载，确认资源不持续增长。
- 真机：在已提供的两台 iPhone Safari 上单独验收玻璃、拖动、短屏放大与脉冲；自动化结果不替代实际震动确认。未完成的真机检查明确标记待验收。
- 发布：使用指定 V6 站点，一次发布消费者、开发和审计三个入口；发布后回读部署状态、资源清单和线上实际页面。V5 不重发、不重定向，仓库不连接 Netlify 自动部署。

实施基于当前干净的 main，使用独立任务分支，保留原始素材、上游来源、用户请求、最终计划、验证记录和提交 SHA；按阶段提交并按已有授权推送、合并，分别核实 Git 与线上状态。

计划批准前仅完成只读核对与计划收敛，尚未修改工程、生成正式资产或部署 V6；2026-10-17 用户要求实施此计划。
