# V5 城市结构母版

画幅来自中国杯 PSD 的外框图层：`5433 × 2365`（600 ppi，外框坐标 777,2243,6210,4608）。花纸导出 PSD 是 `6409 × 3858`、400 ppi 的拼版，作为固定纹饰对齐参照，不直接作为城市画布。

每城 SVG 有 `lines`、`fill`、`holes`、`guides` 组。线条和填面是可编辑的轮廓路径，未嵌入位图；它们由审核中的黑线母稿矢量化，不宣称人工中心线钢笔路径。孔洞只扣除填面，不生成额外凹凸。模板中的底线和文字区域是辅助线，默认隐藏。

北京根据 2026-10-15 的补充请求重新生成：去前景波浪与多余山线，建筑落到底线；以原 PSD 天坛图层约束屋顶、栏杆、门窗和台阶密度。原橙线 JPEG、第一版黑线和去波浪候选均保留在 `../../source/v5/`，提示词一并保存。当前生成像素为 1899 × 828。深圳沿用原 1900 × 828 黑线母稿。4096 × 1783 是运行导出尺寸，不表示原生生成 4K。

## 批量制作

1. 在 `cities.json` 中添加城市 ID、名称、源稿相对路径和提取模式。黑线母稿使用 `black-ink-alpha`：建筑内部不透明白色，背景与真实开口透明。橙线白底输入可用 `orange-ink`，但必须人工复核闭合填面。
2. 首次运行编译器建立 SVG；其后直接编辑 SVG 的结构与填面，移除多余细节、检查真实孔洞和底线。轮廓与内部细线参考原 PSD 和深圳母稿，不以超分增加细节。
3. 常规编译只读取现有 SVG。只有显式 `--trace` 才从源位图重建并覆盖 SVG；人工修稿后不要使用该选项。
4. 编译器按源稿等比缩放和平移进入母版，V4 的 `.82/.047/0` 放置变换只应用一次。结构通道 R=线，G=覆盖（含线），B=0；两者为非颜色数据。法线来自线遮罩的浮点高度，不从颜色或阴影提取。
5. 每城运行包只有结构遮罩、共用法线、独立文字和缩略图。五种颜色在运行时调色，不复制整套图样。城市名称通过独立字体绘制，不依赖生成图片的文字。
6. 通过 Python 素材检查、浏览器两端/中间值及同机位近景核对后再加入前台选择目录。城市入口从编译后的目录自动生成，无需逐城复制材质代码或前台组件；20 城名单尚未确定。

## 复现

使用项目内环境安装 `tools/requirements-v5.txt`（Pillow、NumPy、vtracer），Node 依赖来自应用锁文件。所有安装缓存和临时输出放项目 `.codex-work/`。

```sh
python3 tools/compile-city-v5.py
python3 tools/test_city_v5_assets.py
npm test
npm run build -- --outDir .codex-work/tmp/v5/build
QA_URL=http://127.0.0.1:5225/ npm run qa:v5
```

本机使用已有 Python 3.12 和项目内 vtracer 缓存运行；无需外部 AI API key。新图使用内置 ImageGen，保留完整提示词和来源。网页里的浮雕参数为法线强度，不是毫米；没有工厂线宽/间距数据，不能据此声明已满足实物生产规格。
