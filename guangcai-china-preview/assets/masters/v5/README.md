# V5 城市结构母版

画幅来自中国杯 PSD 的外框图层：`5433 × 2365`（600 ppi，外框坐标 777,2243,6210,4608）。花纸导出 PSD 是 `6409 × 3858`、400 ppi 的拼版，作为固定纹饰对齐参照，不直接作为城市画布。

每城 SVG 有 `lines`、`fill`、`holes`、`guides` 组。2026-10-15 的地标重构将北京、深圳改为逐建筑组合：祈年殿从原 PSD alpha 图层提取真实轮廓，其余建筑为代码定义的可编辑矢量轮廓与中心线。不是嵌入位图。前景建筑遮挡后方线条，孔洞只扣除填面、不自动生成额外凹凸。模板中的底线和文字区域是辅助线，默认隐藏；填色闭合边界不自动转成可见金线。

北京去掉前景波浪、修正央视左侧出线，长城在最后一座城楼后顺曲线落底。深圳保留原建筑序列并移除右侧长桥，以市民中心屋檐收尾。原橙线 JPEG、此前黑线和本次 ImageGen 研究稿均保留，后者因边界/杂点问题未直接接入。原位图分别为 1899 × 828 与 1900 × 828；当前 SVG 使用 1900 × 828 建筑坐标组合，再等比进入 PSD 母版。4096 × 1783 是运行导出，不冒充 AI 原生 4K。

## 建筑单元

`landmarks/manifest.json` 列出北京 7 个和深圳 9 个独立单元、来源与哈希。每个单元保留城市坐标，可独立审阅。`build-city-landmarks.py` 是可重复构建入口；显式执行会重建两城 SVG 与单元，手工修改后的 SVG 不应随意运行该重建命令。普通编译只读取保存的 SVG。

```sh
python3 tools/build-city-landmarks.py  # 仅在有意重建地标时执行
python3 tools/compile-city-v5.py
```

新的批量顺序：先确认地标轮廓及主要结构 → 分别建立填面和真实孔洞 → 组合并处理遮挡 → 检查建筑底边/曲线收尾 → 导出运行通道 → 同机位验证。现代建筑线宽在 1900 坐标中为外轮廓 2.8、内结构 1.65；这是网页绘图基准，不是工厂最小制造线宽。原 PSD 祈年殿保留其自己的线条层次。

## 批量制作

1. 在 `cities.json` 中添加城市 ID、名称、参考源稿与制作模式。建筑单元母版使用 `authoring.mode=landmarks`，记录独立绘图坐标与底部基准。旧位图流程仍支持 `black-ink-alpha` 与 `orange-ink`，但需人工复核填面。
2. 首次运行编译器建立 SVG；其后直接编辑 SVG 的结构与填面，移除多余细节、检查真实孔洞和底线。轮廓与内部细线参考原 PSD 和深圳母稿，不以超分增加细节。
3. 常规编译只读取现有 SVG。旧位图母版只有显式 `--trace` 才会被重建；建筑单元母版拒绝 `--trace`，避免参考位图覆盖矢量重构。母版来源哈希用于追溯，参考位图不再决定当前地标几何。
4. 编译器按源稿等比缩放和平移进入母版，V4 的 `.82/.047/0` 放置变换只应用一次。结构通道 R=线，G=覆盖（含线），B=0；两者为非颜色数据。法线来自线遮罩的浮点高度，不从颜色或阴影提取。
5. 每城运行包只有结构遮罩、共用法线、独立文字和缩略图。五种颜色在运行时调色，不复制整套图样。城市名称通过独立字体绘制，不依赖生成图片的文字。
6. 通过 Python 素材检查、浏览器两端/中间值及同机位近景核对后再加入前台选择目录。城市入口从编译后的目录自动生成，无需逐城复制材质代码或前台组件；20 城名单尚未确定。

## 复现

使用项目内环境安装 `tools/requirements-v5.txt`（Pillow、NumPy、vtracer），Node 依赖来自应用锁文件。所有安装缓存和临时输出放项目 `.codex-work/`。

```sh
python3 tools/compile-city-v5.py
python3 tools/test_city_v5_assets.py
npm test
npm run build -- --outDir .codex-work/tmp/v5/build
QA_URL=http://127.0.0.1:5225/ npm run qa:v5
```

本机使用已有 Python 3.12 和项目内 vtracer 缓存运行；无需外部 AI API key。新图使用内置 ImageGen，保留完整提示词和来源。网页里的浮雕参数为法线强度，不是毫米；没有工厂线宽/间距数据，不能据此声明已满足实物生产规格。
