# 内存提醒 / Memory Watch

轻量 macOS 顶栏 App：每 5 秒读取进程的物理内存占用量（`ri_phys_footprint`，包含压缩内存的计账），发现高占用或快速增长时发送系统通知。仅使用本机数据，不自动结束进程，不上传数据。

## 已安装版本

- App：`~/Applications/Memory Watch.app`；顶栏只显示一个固定宽度的小芯片图标，没有文字。高占用、快速增长或采样失败时变红，恢复正常后自动还原；暂停时换成暂停图标。通知冷却期间，仍存在异常则保持红色。
- 自启动：`~/Library/LaunchAgents/local.shuangsu.memory-watch.plist`。当前用户登录后启动，无需保持终端打开。
- 日志：`~/Library/Logs/Memory Watch/events.log`，另保留一个轮转文件，总量约 512 KiB。
- App 运行不依赖 Python、Homebrew 或网络；支持 macOS 13 及以后版本，构建产物为本机架构。本地 ad-hoc 签名，未做发行公证。

首次运行请允许“内存提醒”的通知。点击顶栏 →“发送测试通知”检查是否实际收到；系统“通知”设置和专注模式会影响横幅及声音。即使通知受阻，菜单和日志仍保存告警。顶部进程菜单显示 PID，点击可打开活动监视器；点击系统通知也会打开活动监视器。

## 默认规则

| 条件 | 行为 |
|---|---|
| 单进程连续两个采样点 ≥ 2 GiB | 高占用提醒 |
| 单进程 ≥ 4 GiB | 当次采样严重提醒 |
| 最近最多 60 秒内增长 ≥ 512 MiB，且当前 ≥ 1 GiB | 快速增长提醒；至少有 10 秒观测 |
| 同一进程持续异常 | 最多每 5 分钟重复一次；严重程度提升可立即提醒 |

同一轮多个异常合为一条通知；通知中心复用一条记录，完整事件保存在轮转日志。首次采样发现严重高占用也会提醒。PID 重用、进程退出和长时间休眠会重置或自然清除相应历史。

菜单可切换“宽松阈值（4 / 8 GiB）”，快速增长规则保持不变；此选择会保存。暂停监控、关闭登录自启动、退出 App 均可从菜单完成。退出仅结束当前运行；需要下次登录也不启动，请先取消“登录时自动启动”。

## 边界

监控所有当前账号可读取的进程；部分系统进程受 macOS 权限限制，菜单会显示不可读数量，无需管理员权限。按单个进程计量，不把一个 App 的所有 Helper 合并；正常的大型任务也可能触发阈值，这不是内存泄漏的自动诊断。采样间隙内突发耗尽内存、系统已完全失去响应或通知被系统阻止时，无法保证及时提醒。

## 构建、验证和安装

在此目录运行（构建需 Xcode Command Line Tools，安装脚本需 Python 3）：

```sh
zsh build-app.sh
python3 install_app.py
```

安装包位于项目 `.codex-work/memory-watch-build/Memory Watch.zip`。构建脚本执行原生告警逻辑自测；可对已安装 App 的 `Contents/MacOS/MemoryWatch` 运行 `--snapshot` 只读检查现场进程，或 `--test-notification` 验证系统通知是否投递。签名在一个很小的一次性临时目录完成后打包，避免文稿同步服务重新附加 FinderInfo 导致验签失败。安装时对同标识旧版本做项目内备份，遇到同路径不同 App/Agent 则停止。

## 可选命令行脚本

App 与 Python 脚本是独立入口，通常只运行 App，避免重复提醒。脚本仅依赖 Python 3 标准库，不设置自启动。

```sh
python3 memory_watch.py --once
python3 memory_watch.py --match SceneKit
python3 memory_watch.py --warn-gib 3 --critical-gib 6
python3 memory_watch.py --test-notification
python3 memory_watch.py --dry-run --duration 15
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -v
```

也可双击 `启动内存提醒.command`，通过 Ctrl+C 停止。脚本日志位于项目 `.codex-work/memory-watch/`，相同状态目录只允许一个脚本实例。命令行通知经 `osascript` 提交，其通知权限来源与原生 App 不同。

## 卸载

先在顶栏取消“登录时自动启动”，再退出 App。随后可移除 `~/Applications/Memory Watch.app`。历史告警仍位于上述日志目录；源码和项目内构建产物独立保留。
