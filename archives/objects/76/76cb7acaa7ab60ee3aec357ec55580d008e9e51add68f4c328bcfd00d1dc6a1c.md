1. 核对旧站 guangcai-no1 的真实项目与发布 ID，以及现有 CLI 登录。
2. 构建当前中国杯预览，以允许列表将当前两页与所需资产复制到项目内发布暂存，保存逐文件 SHA-256；源 PSD、PDF 和旧花纸留在本机。
3. 在原团队创建独立 guangcai-no1-china 站点，以明确的新项目 ID 发布生产版本，不连接 Git 自动部署。
4. 回读生产状态、HTTPS 域名、资源哈希、浏览器实际模型、反射开关和手机视口，验证缺失资源 404 与缓存规则；旧站发布 ID 保持一致。
5. 保存部署 ID、固定版本、线上截图与完成记录，更新 README。保持非 Git 状态，不初始化 Git。

## 公网验收发现后的修正（2026-10-12）
首轮 Netlify 状态 ready，但真实公网浏览器的 PNG 贴图传输较慢，并出现 HTTP/2 中断。完成上线必须包括真实完整模型，因此追加以下修正，再向前发布：

- 16 张实际运行时贴图派生为无损 WebP，解码 RGBA 与原 PNG 完全一致；原 PNG、高度与 PSD 源文件保留。
- 固定花纸高度源不参与当前法线渲染，初始加载只传输实际使用的四种通道。
- 贴图请求最多并发 4 个，失败最多尝试 3 次，以独立查询参数重新请求；仅网络 URL 重试，损坏 data URL 立即报错。
- 初始加载提示持续到全部固定资产、城市资产、文字和局部反射完成，避免部分载入时提示成功。
- 构建前自动生成和逐像素核对运行时副本。重新执行完整 43 项生产预览回归，加入首请求中断后的自动恢复验证。
- 新发布仍使用同一 -china 站点，重新回读 published deploy 和公网模型。对全部文件核对 Netlify 发布索引的 SHA-1 与大小，对 HTML／JS／CSS 另外核对公网响应字节，并解码网页实际使用的图像。

最终请求配置为并发 4 个、单次 120 秒，最多 3 次；避免慢连接下在 45 秒处主动取消仍在传输的无损大图。网络版仅调整传输调度，不修改贴图像素或材质视觉参数。
