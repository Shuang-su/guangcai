# 为 APEC 添彩 H5 首期落地规划

**一、规划基线与首期目标**

以[《H5 双阶段功能文档 V1.0》](/Volumes/Prism_初号機/广彩/文档/为APEC添彩_H5双阶段功能文档_V1.0.docx)为页面与业务流程基线，以本次讨论中明确的调整覆盖原文冲突。首期目标是形成可实施、可操作、可验收的 H5 前端方案，明确哪些是真实功能、哪些是交互示意、哪些需要后续资产或后端接入。

本次锁定以下边界：

- **云上赏真瓷属于独立的 3DGS 实物展示模块。** 位于引导视频之后，首期不制作、不加载、不开放入口；扫描资产到位后另行接入。
- **创作区使用普通 Web3D 模型。** 保留“东方雅韵五次添彩”的选择流程，器物可真实旋转、缩放、移动。
- **五步选择与最终成果完全分离。** 首期只演示选项、选中状态、切换和保存；不改变模型，不映射款式，也不根据选择改变海报。
- **成果使用固定的已有完整款式。** 默认采用现有“花蝶·金地”材质包，海报与成果 3D 展示同一款式，明确标注效果示意。
- **身份、真实作品存储、分享归因、榜单及领奖由后端同事后续接手。** 本轮规划页面状态、前端演示和接口边界，不把模拟数据视为业务能力已完成。

原文中的“DIY 不拆步骤”“每步发生可验证的 3D 状态变化”“海报按用户选择生成”，均需要在本轮有效计划中标明为已调整内容，避免后续按两个版本验收。

**二、页面流程与 3D、2D 分工**

首期主路径为：

**加载 → 引导视频 → 白瓷落定与开始添彩 → 五次添彩 → 成果准备 → 结果与海报 → 查看 3D／分享引导／共彩榜单。**

| 页面或模块 | 实现形式 | 首期具体行为 |
|---|---|---|
| P00 加载 | 2D 页面与真实资源状态 | 只统计开场资源；不请求 3DGS。资源不可计量时显示加载状态，不编造百分比 |
| P01 引导视频 | 实际视频文件＋HTML 控件 | 播放、跳过、播放受阻提示；结束或跳过后进入白瓷落定页 |
| P02A 白瓷落定 | 视频尾帧或同器型渲染图＋2D 按钮 | 按功能文档保留为静态承接页，不提供旋转缩放；同步出现“开始添彩”及首页、共彩榜导航 |
| P04 五次添彩 | **真实 Web3D 器物＋2D 选择界面** | 杯体旋转缩放；五步选项可操作，选择不影响杯体或最终成果 |
| P05 成果准备 | 真实任务状态＋轻量动效 | 加载固定材质包、生成对应海报；完成后进入结果页，不使用虚假的 AI 生成进度 |
| P06 结果与海报 | 2D 排版＋实际生成的图片 | 长按保存、查看 3D、分享引导、重新体验；展示“当前为预设款式效果示意，与五步选择暂未关联” |
| P10 成果 3D | **真实 Web3D** | 展示与海报一致的固定款式，支持旋转缩放，返回结果时不重新生成 |
| P09／P11／P12／P13 | 2D 页面 | 保留详情、首页、榜单、规则的完整路由；前端演示数据与真实服务明确区分 |
| P14A／P14B／P15 | 2D 结果及表单状态 | 保留邮寄与现场领取两种页面定义；演示阶段不采集真实地址、不产生有效领取码 |
| 后续云上赏真瓷 | **3DGS＋2D 控件** | 首期只保留模块接口与入口条件，不用视频或旋转图片冒充扫描模型 |

导航规则沿用原文中不冲突的部分：开场、五次添彩、成果和详情页隐藏一级导航；白瓷落定、首页和榜单显示首期两项导航。未来 3DGS 上线后，才增加赏瓷导航。

首次访问走完整入口；本地已有完成状态进入榜单演示；看过开场但未完成时进入首页，有草稿可继续。分享落地页的“我来添彩”直接进入创作，不强制重播开场。

**三、五次添彩与真实 Web3D 的实现边界**

五次添彩放在**同一个创作页面**中，使用五个可返回的步骤面板。桌面保持器物与选项并排，手机采用上方器物、下方选项布局；不照搬概念图中的整张横版展板。

| 步骤 | 首期选项 | 实际反馈 |
|---|---|---|
| 为开放添一线 | 向海而开、海路交汇、星湾相连、潮汐相拥 | 更新选中态及草稿记录 |
| 为创新添一形 | 繁花盛放、百鸟和鸣、蝶舞新生、花鸟相生 | 更新选中态及草稿记录 |
| 为合作添一重 | 交织、相映、共簇、接力 | 更新选中态及草稿记录 |
| 为繁荣添一彩 | 海纳蓝、焕新紫、同心金、共融绿、繁盛红 | 更新色卡选中态；不宣称改变瓷器颜色 |
| 为未来添一愿 | 山海相连、新意共生、携手同行、共赴繁荣 | 更新祝愿选中态；本期不开放自由文本 |

每步单选，未选择时不启用该步“下一步”；已经完成的步骤可返回修改。五步完成后进入固定成果示意。刷新、查看规则再返回、生成失败返回时保留选择；“重新体验”才清空。

概念稿可以用于选项的**二维意向缩略图**，需去除烘焙文字、统一裁切和比例；选项名称、说明、按钮和选中态均由真实界面实现。概念图中的浮空花鸟、枝蔓延展、金线生长、立体纹样浮出等，不列入首期 3D 行为。

Web3D 复用[现有一号杯工程](/Volumes/Prism/Codex/guangcai-viewer-20260929/outputs/guangcai-viewer)，保留原工程作为独立观察器，将器型、材质、相机与手势能力抽成 H5 可调用模块：

- 创作过程中展示同一套中性白瓷模型，选项不触发材质替换。
- 完成后一次性应用“花蝶·金地”完整材质包；其余已有款式保留为资源，不新增用户选款步骤。
- 海报中的杯子由这一模型和材质实际渲染，不用另一张生成图片代替。
- 保留杯、盖、把手、碟的真实几何及独立装饰区域；不因概念图造型不同而悄悄修改现有器型。
- 缺失贴图时保留上一有效状态并提示重试，不混合新旧材质，不展示错误款式后声称成功。

当前工程的花纸是 AI 风格新稿，法线与金属遮罩属于艺术近似，因此成果命名使用“数字款式示意”，不声称原厂纹样复刻或实物扫描。品牌 PDF 用于理解瓷釉、金彩、留白及产品关系，不能把其中不同器型视为同一模型。参考：:codex-file-citation{path="/Volumes/Prism_初号機/广彩/文档/【国瓷永丰源】中秋礼·广彩传承(1).pdf" purpose="source"}

**四、视觉、素材与前后端交接**

视觉采用“东方雅韵的留白与版式＋中国红的关键强调＋APEC 参考中的多彩连接”，两套新参考分别承担明确用途：

- **水墨浅底、城市山海：** 用于首页、规则、榜单和海报的环境氛围，降低纹理对文字的干扰。
- **浅底深蓝、彩色飘带：** 用于开场叙事、阶段提示、轻量转场和海报边缘。
- **中国红：** 用于主行动、当前选中态、印章式点缀与完成态的重点区域。
- **暖金：** 用于细线、分隔和少量装饰；杯体金彩由真实材质与灯光表现。
- **器物观察区域：** 使用简洁、稳定的背景与中性照明，避免彩色背景光把白瓷染色、影响款式判断。

这些颜色先作为项目视觉变量，不把截图采样值称为官方色值。现有海报中的完整文字和标识不直接作为页面背景使用；移动端文字、按钮、列表和表单都保持可排版、可交互。Frame 4 用于器物主次关系和移动端构图参考，不作为整站红金皮肤的唯一依据。

素材按三类处理：

| 状态 | 内容 | 处理方式 |
|---|---|---|
| 已有可复用 | 一号杯几何、三套完整材质、实拍参考、概念图片、APEC 视觉参考 | 建立资源清单，记录用途、版本、来源和是否用于真实 3D |
| 首期需制作 | 开场视频、白瓷尾帧、分层背景、规范化选项缩略图、海报模板 | 交付可编辑源文件和运行时文件；不能只交效果图 |
| 后续缺失 | 3DGS 扫描资产、真实作品与榜单服务、身份与分享接入 | 明确依赖与接口，不安排假实现充当完成 |

开场按固定视频叙事规划，不额外引入“按住微光”“滑动推动光路”等未经确认的游戏操作。正式视频未到位时，可测试播放与跳过流程，但该模块不能通过视觉交付验收。播放受浏览器限制时提供可点击播放入口，并根据真实播放结果更新界面。[MDN 播放行为说明](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)

前端继续使用现有 Vite、TypeScript、Three.js 技术基础。身份方案与服务部署由后端决定，前端只约定以下最小数据边界：

- **活动配置：** 发布阶段、赏瓷入口开关、规则版本、结果公布状态。
- **创作草稿：** 五步选项及当前步骤；本期不参与成果计算。
- **成果记录：** 器型版本、固定款式版本、海报资源及“示意成果”标识。
- **后端服务边界：** 作品、分享落地、榜单、公开参榜、获奖与领取状态。
- **未来 3DGS 模块：** 资产加载、就绪、失败、退出与资源释放；资产格式和渲染器待真实扫描数据到位后验证。

前端演示使用独立的本地数据适配层。不得把本地编号当作跨设备作品链接，不虚报“分享成功”、真实排名或有效共彩归因。

**五、实施顺序与验收标准**

按下列顺序推进，每一阶段交付可核查的结果：

1. **修订功能基线与低保真流程。** 整理页面职责、导航、返回路径、五步状态、异常状态，并明确上述对原文的覆盖项。
2. **制作真实 3D 验证样机。** 验证手机上的旋转缩放、中性白瓷、完成后应用固定材质、实际渲染海报及 P06／P10 一致性。
3. **完成视觉与动效制作。** 将两套 APEC 参考落实为可编辑版式、分层素材和真实视频，先检查器物可读性，再扩展到所有页面。
4. **贯通前端演示。** 完成五步、本地恢复、结果、海报、详情、榜单和规则的页面流，交付后端接口样例与明确的模拟数据说明。
5. **后续接入真实服务与 3DGS。** 各自经过独立验收后启用；不自动继承前端演示的“已完成”状态。

验收重点：

- **功能真实性：** 拖动杯子确实改变三维视角；缩放不穿模、不丢失器物。五步只改变选中状态，最终成果保持固定，不出现与实际能力矛盾的描述。
- **成果一致性：** P06 海报与 P10 的器型、款式和材质版本一致；返回不重复生成；海报为可长按的真实图片元素。
- **流程完整性：** 首次、重返、草稿恢复、分享落地、规则返回、重新体验均无死路；首期无 3DGS 请求或误入入口。
- **错误处理：** 覆盖视频受阻、资源超时、贴图失败、海报生成失败和 WebGL 不可用。无法显示 3D 时明确说明并提供重试／返回，不用图片伪装可交互模型。
- **移动端表现：** 覆盖 360、390、430 像素宽度及常见长屏；实际设备验证单指、双指、长按保存和页面切换。以交互时稳定达到约 30 fps 为初始目标，超出负载时优先降低像素比、阴影和贴图档位。现有物理材质成本需要实测，不能以构建通过代替性能验收。[Three.js 材质性能说明](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)
- **交付证据：** 保留可编辑源码、素材清单、真实操作录屏、多视角截图、已实现／仅示意／待接入清单；3DGS 与正式后端不计入首期已完成范围。

本计划默认交付移动端 H5 前端规划与后续可操作演示，使用现有一号杯作为器型基础；不新增扫描、不新增任意纹样生成、不实施身份接入。**当前最关键的交付标准，是页面确实可操作、3D 确实可交互、示意部分明确可辨，且每个承诺的视觉效果都有对应资产或实现路径。**
